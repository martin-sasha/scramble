# SASHA client files (PoC)

Browser files for SASHA's text protection, client mode. Generated by `poc/build-embed.mjs`; do not edit by hand.

| File | Loaded |
| --- | --- |
| `sasha-protect.js` | by the page (the only file the page names) |
| `sasha-grain.js` | always, by `sasha-protect.js` |
| `sasha-brotli.js` | only when the site's font is WOFF2 (Google Fonts are) |
| `sasha-face.js` | only when the site's font cannot be read or lacks characters |

`sasha-protect.js` loads the others from its own folder, so keep the four files together.

## Serving them from GitHub

Use jsDelivr, not `raw.githubusercontent.com` (GitHub serves raw files as `text/plain`, which browsers refuse to run
as a script). Tag a release and load that tag, so a later push does not change live pages:

```
https://cdn.jsdelivr.net/gh/<github-user>/<repo>@v0.1.0/sasha-protect.js
```

(If the files are in a subfolder of the repo, add it to the path.)

## Webflow

1. Site settings → Custom code → Head code:

   ```html
   <style>[data-sasha-article]:not([data-sasha-ready]) :is(p,li){visibility:hidden}</style>
   <script src="https://cdn.jsdelivr.net/gh/<github-user>/<repo>@v0.1.0/sasha-protect.js"
           data-publisher="SASHA" defer></script>
   ```

2. In the Designer, on the CMS template page: select the Rich Text element with the article body → Element settings →
   Custom attributes → name `data-sasha-article`, value the article's six-hex-digit ID (e.g. `5A5A5A`). With no value
   there, put `data-id="5A5A5A"` on the script tag instead (one ID for every article).

3. Publish. Check in the browser console: `await SASHA.ready` lists the font mode used.

PoC: the page still carries its plain text in the HTML, so this does not stop scrapers or AI crawlers. Without an
article ID, or if anything fails, the original text is shown unchanged.
